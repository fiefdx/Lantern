# T0.5 — ChatForm / HostForm / ClientForm

**Done.** Three files, each split `.cs` (behaviour) + `.Designer.cs` (design):

* `UI/ChatForm.cs`, `UI/ChatForm.Designer.cs` — abstract base, Figures 3 **and** 4 *(not since `v1.0.4`: design view cannot open an abstract class, and the shared layout is most of both windows — see `docs/notes/design-view.md`)*
* `UI/HostForm.cs`, `UI/HostForm.Designer.cs` — adds **New** / **Delete**
* `UI/ClientForm.cs`, `UI/ClientForm.Designer.cs` — adds **Leave**, room editing disabled

## Layout (TableLayoutPanel, 3 cols × 3 rows)

| | col 0 (190px) | col 1 (%100) | col 2 (170px) |
|:--|--|--|--|
| row 0 | `pnlRoomHeader`: “Rooms” + `pnlRoomActions` | — | “Members (n)” |
| row 1 | `lstRooms` | `rtbChat` (read-only `RichTextBox`) | `lstMembers` |
| row 2 | `btnShare` | `txtMessage` | `btnSend` |

Menu: `File ▸ Quit`, `Edit ▸ Rename room`, `View ▸ Clear chat pane`, `Help ▸ About`.
Bottom: `StatusStrip` → “Status: server online” / “Status: connected”.

Role management buttons are injected into the base form's `pnlRoomActions` strip, so the
host and client windows stay pixel-identical except for those buttons — exactly the
“one chat form for both roles” idea from the design section.

## Behaviour contract exposed to the rest of the app

Base `ChatForm`:
* `ChatForm(string nickname)` / `Nickname`
* events `RoomSelected`, `SendRequested`, `ShareRequested`, `QuitRequested`
* `SetRooms(names, select?)`, `SetMembers(nicknames)`, `AppendMessage(sender, body, isNotice)`
* `SetStatus(message)`, `SetBusy(bool)`, `UpdateTitle(role)`, `SetRoomEditingEnabled(bool)`
* Enter sends, Shift+Enter newline
* **Send/Share are disabled** while busy, while the message box is empty, or when no room
  is selected (double-send guard)

`HostForm` adds `CreateRoomRequested` / `DeleteRoomRequested`; `ClientForm` adds
`LeaveRoomRequested`.

## Naming

The wireframes label the left panel “Groups”; per the spec the application says
**Room** everywhere (“Room 1”, header “Rooms”). `ChatFormTests.LabelsSayRoomNotGroup`
guards this.

## Temporary demo data

`LoadDemoData()` in each role form paints dummy rooms/members/transcript so the shell is
clickable today. **T0.7** replaces these calls with `FakeChatService`, and **T2.7** binds
`IChatService` events. Nothing else depends on the demo data.
