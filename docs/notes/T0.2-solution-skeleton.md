# T0.2 — Solution skeleton

**Done.**

```
Lantern.sln
Lantern.slnx                       (removed — kept classic .sln for VS 2022)
src/Lantern/Lantern.csproj         WinForms exe, net10.0-windows
src/Lantern/Program.cs             entry point, opens UI.StartupForm
src/Lantern/UI/                    forms + dialogs
src/Lantern/Core/                  chat service / session / browser / sound
src/Lantern/Domain/                Message hierarchy, Room, User, validation
src/Lantern/Storage/               RoomDto, IRoomStore, JsonRoomStore
src/Lantern/Transport/             IBtServer / IBtClient / IClientLink, FrameCodec
src/Lantern.Tests/                 xUnit tests
```

Decisions baked into `Lantern.csproj`:

* `net10.0-windows` + `UseWindowsForms` (**F1**)
* `Nullable=enable`, `ImplicitUsings=enable`
* `TreatWarningsAsErrors=true` — contract rule 1 ("compiles without warnings") is
  enforced by the build, not by convention.
  Consequence: every `*.Designer.cs` starts with `#nullable enable` because the
  designer declares `IContainer? components`.

## How to use

```powershell
dotnet build Lantern.sln     # must print "0 个警告 / 0 个错误"
dotnet test  Lantern.sln
dotnet run --project src/Lantern/Lantern.csproj
```

`SolutionSmokeTests.AppAssemblyIsLoadable` proves the test project sees the app
assembly, so domain/core tests can reference app types from the start.
