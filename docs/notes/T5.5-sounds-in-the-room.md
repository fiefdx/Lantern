# T5.5 — a room that makes a noise

Milestone M5 · task T5.5 · area Net

## What the task asked for

`SoundNotifier` on `SoundPlayer`: a short sound when a new message arrives (F10), a distinct sound when a
file finishes.

## Two sounds, because they are two different reasons to look up

"Somebody said something" and "the file is here, whole" are not the same event, and one noise for both means
the person comes back for the wrong one and stops coming back for the right one. So:

| Cue | When | File |
| --- | --- | --- |
| `Message` | a message lands in a room this window is showing — text, picture, or somebody joining | `Media/message.wav` |
| `FileReady` | a transfer this window was watching ended whole | `Media/file-ready.wav` |

The two wavs are 5 KB and 15 KB, 22 kHz mono, generated rather than found: a short 880 Hz blip with an attack
and a decay for a message, and a two-note rise (660 → 990 Hz) for a file. Written out by a twelve-line
Python script, so they can be made again on any machine instead of being a file somebody committed once.

## Files next to the program, not the system's sound scheme

The obvious shortcut is `SystemSounds.Asterisk.Play()`. It was not used, because that scheme is different on
every machine, and can be set to silence by whoever set the machine up — which makes F10 depend on settings
this program does not own. Shipping two small wavs means the sound is the same in the lab as on any other
laptop, and replacing `Media/file-ready.wav` changes the sound without opening the code.

`SoundPlayer.Play()` is asynchronous, so the message loop is never waiting on a sound; the players are held
for the life of the notifier (`Play()` on a disposed player plays nothing) and a missing file is remembered as
missing rather than re-checked on every message.

## What does not make a noise

* **A file that was announced but has not arrived.** The transcript line comes with `FILE_META` and the bytes
  take however long they take; noising at both ends is two noises for one delivery. `MessageArrived` ignores
  `MessageKind.FILE` for exactly this reason, and the noise comes when `FileDone` says the transfer ended.
* **A file that stopped.** Stopped is not finished. A cheerful sound after a failed transfer is the sort of
  thing that gets a person switching the sound off — which costs them every message afterwards.
* **This window's own messages.** Nothing echoes them back, so nothing reaches the notifier.

And anything the machine cannot do is swallowed: no sound card, a session with no window station, a wav
truncated by a bad copy. The message arrived; that was the part that was asked for.

## Who decides that a window is allowed to be noisy

Not the window. `ChatForm` has no notifier of its own — `AttachSounds` is called by the composition root
(`StartupForm.Open`, where the host or client window is actually built). A `ChatForm` on its own, in a test
runner or in whatever gets built next, is silent until somebody asks it to make a noise. Attaching twice throws
rather than quietly playing everything twice.

There is also a process-wide switch, `SoundNotifier.Muted`, which the test assembly sets in a
`[ModuleInitializer]`: four hundred windows open and close across a run of this suite, several of them through
the same code path the program uses, and a test cannot hear a beep — so there is nothing to gain and only a
noise in somebody's headphones to lose. `Muted` suppresses the *speaker*, not the decision: a notifier built
with an injected player still records what it was told to play, which is how the tests below can assert on a
sound without one.

## Tests

`src/Lantern.Tests/SoundNotifierTests.cs` (12): a message makes the message noise · a picture and a newcomer
too · announcing a file is not the same as having it · a file that arrived makes a *different* noise · a file
that did not finish makes none · a window nobody asked to be noisy says nothing · a broken sound card does not
break the chat · the two sounds are files next to the program and they are not the same file · a window told to
make a noise beeps when something arrives · it makes the file noise when a file finishes, and not before · a
file stopped on the way makes no file noise · a window does not get two notifiers.

389 tests in the suite.

A **Mute** menu item. `SoundNotifier.Enabled` is there for it and `View` has the space, but the proposal asks
for the sounds, not for a switch, and a switch nobody asked for is a menu item to test and translate.
