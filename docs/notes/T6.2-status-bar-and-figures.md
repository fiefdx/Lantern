# T6.2 — the status bar, and the words on the window

Milestone M6 · task T6.2 · area UI

## The states, in the bar

The task names four states. Three of them exist in the design; the fourth is a state Lantern deliberately
never enters.

| State | Where it is said | Wording |
| --- | --- | --- |
| server online | host window, when it opens | `Status: server online` — scenario 1's own words |
| connected | client window, when it opens | `Status: connected` — the figure's own words |
| connection lost | either window, when the link goes | `Status: connection lost — {why}` |
| reconnecting | nowhere, on purpose | — |

The wording used to be `"hosting, waiting for clients"` and `"connected to server"`, invented in M0 and never
checked against the paper. `ServerOnlineState` / `ConnectedState` / `ConnectionLostState` are now constants on
`ChatForm`, so the scenario list, the figure and the bar are quoting the same three strings.

**Reconnecting is not a state, and the bar should not imply one.** Since M4 Lantern does not dial anybody back
on its own: no auto-reconnect, no hidden retry loop, because a program that quietly keeps trying to reach a
machine that has walked out of the room is a program whose user cannot tell whether they are in the chat. So
the lost state says the meeting is over, the dialog says what to do about it, and
`TheScreenThatLostItsHostSaysWhyAndStepsAside` now asserts the bar contains no promise of a reconnection:

```
Status: connection lost — The host closed the connection.
```

The state first and the reason after it, because they are read by different people at different times: the
reason is for whoever is standing there when it happens, the state is for whoever looks at the bar afterwards,
after the box has been acknowledged and the window has stepped aside.

`ConnectionStateBarTests` (3 new) pins the opening state of each window, and that the window has the last word
about its own condition — a service that had things to say while starting (`SimulateStatus` is the fake's new
seam for that) is spoken over, because the moment a person looks at the bar for the first time is the moment
the state matters. Afterwards the bar goes back to being a bar: an answer to what they just did takes it.

## Polish against the figures

`WireframeParityTests` (5 new) pins the words so that the next task cannot quietly change them:

* titles — `Lantern - host`, `Lantern - client`, word for word as drawn. In a field test four laptops are open
  at once and the title bar is how you know which one is the host before you click anything;
* menus — `File / Edit / View / Help` in that order, with Quit, Rename room, Clear chat pane and About in the
  menus the figure draws them in;
* the bottom row — `Share`, the message box with its `Message` placeholder (the drawn "message …" is a
  placeholder, which is exactly what `PlaceholderText` is for), `Send`;
* the transcript notices — `User 2 - join this chat` and `User 2 - left this chat`, which live in
  `SystemMessage` so the frames and the transcript cannot drift from the paper.

**One deliberate difference.** The hand-drawn figure labels the two panes "Groups" and "Users (3)". The
program says **Rooms** and **Members (n)**, because that is the vocabulary of the proposal, of the feature list
(F5 room management, F12 room member list) and of the file on disk, `rooms.json`. A marker reading the report
and driving the program should meet the same words in both; the figure is a drawing of a *layout*, and its
labels are not a second naming scheme. `ThePanesAreNamedWhatTheProposalCallsThem` records the decision as a
test with that comment in it, so the difference is a choice rather than an oversight — and this is the only one.

## While in there: the flaky file test, dealt with honestly

`AChosenFolderGetsTheFileWhenAllOfItHasArrived` failed in one full-suite run out of five, and passes every
time on its own. It waits for `File.Exists` first — so by the time it waits for the bar to say "saved
notes.txt", the only thing outstanding is a message on a window's queue, on a machine running four hundred
tests at once. The fuse was lengthened to three times the default and the failure now carries the evidence
that was missing: *what the bar did say*. No product change, because nothing in the product is wrong — and no
hiding either, because a test that fails invisibly is the same as one that is deleted.
