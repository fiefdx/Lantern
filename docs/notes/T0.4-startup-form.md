# T0.4 — StartupForm (Figure 2)

**Done.** `src/Lantern/UI/StartupForm.cs` + `StartupForm.Designer.cs`.

Layout, matching the wireframe:

| Control | Purpose |
|:--|:--|
| `lblNickname` / `txtNickname` | nickname, prefilled with `Environment.UserName`, `MaxLength = 16` |
| `lblHostHint` | “Host a chat: this machine becomes the server” |

| `btnJoin` | **Join** — `Enabled = false` until a row is selected |
| `statusStrip` / `lblStatus` | “Status: idle”, overwritten with validation errors |

## Behaviour

* Every action first runs `ValidationRules.NicknameError`; on failure the action is
  blocked, focus goes back to the box and the reason appears in the status bar.
* `Join` additionally requires a selected server row.
* Buttons are otherwise **not** functional yet — by design (T0.4 says “validated but
  not yet functional”). `NickName` is exposed as `Nickname` for T0.7 to build the service.
* Form is `FixedSingle`, non-maximizable, `MinimumSize` set so anchors behave.

## Conventions this task established

* **All UI design lives in `*.Designer.cs`** (`InitializeComponent`, control fields,
  event wiring). The `.cs` file contains only behaviour.
* Designer files start with `#nullable disable` — that is the nullable-oblivious
  context the designer generates for, and it avoids `CS8618`/`CS8622` under
  `Nullable=enable`. Behaviour files therefore use `object? sender` handlers.

## How to try it

```powershell
dotnet run --project src/Lantern/Lantern.csproj
```

Clear the nickname → the status bar says *“Nickname is required.”* and nothing happens.
With text: *“ready to host as “…” (not wired up yet)”*.

Covered by `StartupFormTests` (STA smoke tests through the `Sta` helper — WinForms
controls cannot be constructed on the default xUnit MTA worker thread).
