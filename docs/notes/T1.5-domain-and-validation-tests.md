# T1.5 — Domain and validation tests (M1 exit)

**Task:** unit tests for T1.1–T1.4, and make `FakeChatService` use the real domain classes.
The last part already happened in T0.7 — the fake holds `Room`, `User` and `Message` objects, not
strings — so this task is the test suite: **46 new tests, 79 in total, 0 warnings.**

## What is now under test

`DomainModelTests` (Figure 7)
* every message subclass reports the right `MessageKind` and carries its own `RoomName`, so a frame
  is self-describing on the wire;
* `Preview` is the single-line rendering the transcript and the tests both rely on, including the
  exact wireframe wording of the join/leave/kick notices;
* `FileMessage.TransferId` ties an announcement to its chunk frames and is unique per message;
* `PictureMessage.ToThumbnail()` scales a real 400×200 PNG to the 160 px cap and **returns null for
  undecodable bytes** — a peer sending junk must not take the transcript down;
* `User` equality is by `ConnectionId`, so two people with the same nickname stay distinguishable;
* `Room` refuses a second member on the same connection, `Append` refuses a message from another
  room, `Transcript` returns a snapshot (not a live view), and 10 000 concurrent `Append` calls from
  `Parallel.For` leave the transcript intact — this is what the server's per-connection read loops
  will do from M2 onwards;
* `FileTransferJob` progress, cancellation, and the fact that it keeps `Path.GetFileName` of what a
  peer sent: **a peer can never dictate a path on this machine.**

`ValidationRulesTests` (T1.4)
* each rule's exact message text, not just pass/fail, because the UI shows these strings verbatim;
* limits are inclusive on both sides (exactly 16 chars is fine, 17 is not);
* `Normalize` trims and collapses inner runs of whitespace, which is what makes `" Room 1 "` and
  `"room 1"` collide in `IsDuplicateRoomName`;
* a multi-line message counts its line breaks — Shift+Enter is allowed, so length must be measured
  on what was typed;
* one test pins the numbers themselves (16 / 24 / 500 / 5 MB). They appear in tooltips and
  placeholders, so changing one has to be a deliberate decision, not a slip.

## Behaviour change found by a test

`FileTransferJob.Fraction` reported `0` for a zero-byte file, while `IsComplete` said it was already
complete. A receiving loop of the shape `while (!job.IsComplete) read bytes` relies on a zero-length
transfer completing immediately; `Fraction` now reports `1` for it, matching the doc comment.

## Deliberately not tested here

`Room`'s `ObservableCollection` is only mutated by the service, and `ObservableCollection` is not
thread-safe, so the concurrency test above uses `Append` (the transcript, which is locked) rather
than member churn. Cross-thread membership is covered from M2 by the end-to-end tests.
