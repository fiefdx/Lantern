# v1.1 manual check — the group window: reading it, looking at a photo, rooms from the menu

Covers the three things asked for after v1.0: **F13** (every message gets a headline — date, time, sender — with
the message itself on the line below, in another colour), **F14** (double-click a photo → a large window that
scales), and **F5** (the host creates and deletes rooms from inside the chat).

The automated suite covers all of it at window level — `TranscriptLayoutTests`, `PictureViewerTests`,
`PictureTranscriptUiTests`, `RoomManagementUiTests` — including reading colours back out of the `RichTextBox` and
asserting that a byte is written nowhere when a photo is opened. What this sheet adds is the four things a test
cannot do: **say whether the colours work on the room's projector**, **judge whether a scaled photo is sharp**,
**feel whether the wheel zooms at a rate a person likes**, and run the whole thing over a **real radio** where the
photo took four minutes to arrive and nobody has forgotten what it was.

## F13 — the transcript reads as a log

| # | Do this | Expect | ✓ | Notes |
|---|---|---|---|---|
| 1 | In A and in B, each send two messages into the room. | Each message is **two lines**: a headline `[2026-03-07 14:05] User 2` and, starting on the line below it, the words. Never name-and-time-and-text on one line. | | |
| 2 | Look at the colours side by side. | Headlines are one colour (dark blue) and every message body another (the window's black). The difference is obvious **from across the room** — if you have the projector, look at it from the back. | | |
| 3 | Read a stretch of four or five messages from two people. | Your eye finds who said what without hunting. The names line up at the left edge of each entry, which is the whole point of the layout. | | |
| 4 | In one message, use **Shift+Enter** to break the line twice, then Send. | One headline, then the body with its own line breaks kept. Only the first line of that message is a headline. | | |
| 5 | Have B **Leave** and rejoin the room. | The notices (`User 3 - left this chat`, `User 3 - join this chat`) have the same two-line shape, in two greys — quieter than a message, because a notice is not somebody speaking to the room. | | |
| 6 | Check the date in a headline. | `YYYY-MM-DD HH:MM`, not just a time. A chat left open since the morning should be able to answer "was that today?" | | |
| 7 | Switch to another room and back. | The rebuilt transcript looks **exactly** like the one you were looking at — same colours, same two lines per message. (This is the path that would have drifted, and a test now holds it.) | | |
| 8 | **Ctrl+A**, **Ctrl+C** in the transcript, paste into Notepad. | Every message reads as headline line then content line. No odd characters, and the blank between entries is a blank, not a stray coloured run. What you can copy out should say what the window said. | | |

## F14 — looking at a picture

Have ready: one photo **over 2000 px** on a side, one small one (a few hundred kB), and an **empty folder** open in Explorer.

| # | Do this | Expect | ✓ | Notes |
|---|---|---|---|---|
| 9 | In B: **Share** → the large photo. In A: **double-click** it — on the thumbnail, then try the headline and the caption too. | A window opens over most of the screen, the photo **fitted** to it, and the toolbar says roughly `Fit — NN %`. Anywhere on the photo's entry opens it: headline, caption and thumbnail are one thing. | | |
| 10 | **Ctrl+wheel** (or **+** / **−**), both ways, and double-click the photo itself. | The photo scales in steps you can stop at, and the percentage changes with it. Double-clicking the photo toggles Fit ↔ 100 %. Nothing in the room is affected while you do it — the window is not modal. | | |
| 11 | Press **0**, then **F**, then **Esc**. | `0` = the photo's own pixels (100 %); `F` = fitted again; `Esc` = close. | | |
| 12 | At 100 % or more on the large photo, on a laptop screen. | The photo is **bigger than the window and it scrolls** — you can reach every corner. It is never cropped with no way to see the rest. Judge the sharpness: a photo stretched to 400 % should look like a photo stretched to 400 %, not like a different photo. | | |
| 13 | Double-click the **same** photo three times; then open a second photo. | Three times = **one** window (raised again, not stacked). Two photos = **two** windows, so you can compare them. Close the chat window: the photo windows go with it. | | |
| 14 | Look at the empty folder from the top of this section, and at `%LOCALAPPDATA%\Lantern\`. | **Nothing new in either.** Opening a photo writes no file — before v1.1 it dropped a copy in app data and opened the system photo viewer. Now **Save to…** (Ctrl+S, or the button) is the only thing that writes, and it writes where you say, keeping the file's own name. Save one and check it opens outside Lantern. | | |

## F5 — rooms from inside the group

| # | Do this | Expect | ✓ | Notes |
|---|---|---|---|---|
| 15 | In A (host): Edit → **New room**, name it, OK. Do it again with **Ctrl+N**. | The dialog appears either way. The room goes into A's list **and** into B's list without anyone pressing anything, and **A is now in it** — the transcript says you are in it and the box is enabled. Making a room you then have to enter is a feature with an extra step. | | |
| 16 | Type a name that already exists. | Refused as you type, with the reason in the dialog, and OK stays unavailable — the room is never half-made. | | |
| 17 | In B (client): open the Edit menu, and look at the room list header. | **New room**, **Rename room** and **Delete room** are all there and all greyed, and New/Delete in the header are greyed too. A client is shown what they cannot do; nothing is hidden, and nothing answers a click with silence. | | |
| 18 | In A: pick a room you are **not** in, Edit → **Delete room** (or **Ctrl+D**). Cancel the confirmation, then do it again and press OK. | The confirmation names the room. **Cancel changes nothing** — the room is still there, on screen and on disk. OK removes it everywhere. | | |
| 19 | In A: delete the room you are **standing** in. | The window returns to having no room: box and Send disabled (F6), and the transcript says which rooms there are and to select one — not blank. Anyone in that room is put out with a notice, and their window still works. | | |
| 20 | In A: rename the room you are in (Edit → **Rename room**). | Everyone's list follows the new name, nobody is moved, and you stay in it — a rename changes what a room is called, not what it is. | | |
| 21 | In A: click in the message box and press **Ctrl+N** then **Ctrl+D**. | The room menu answers, and nothing is inserted into your message. (`Del`, `Ins`, `F` and `+`/`-` stay the typing and looking keys — no shortcut here takes an unmodified key.) | | |
| 22 | Open `%LOCALAPPDATA%\Lantern\rooms.json` in Notepad. | The rooms you made are there with the names you gave them, and each has an `id` — a room is what it is, not what it is called. A room you deleted is gone. | | |
| 23 | Restart A, join again from B. | The rooms are still there after a restart, with their `id`s — so B's window is talking about the same rooms as before, and B does not have to re-join to see them. | | |
